Setup notifikasi WA otomatis penuh (tanpa perlu buka aplikasi ini)

Google Apps Script terjadwal baca/tulis langsung ke Firebase (database yang sama dengan aplikasi ini) dan kirim WA lewat Fonnte — tidak lagi lewat Google Sheet perantara

Data DO, Kendaraan (termasuk KIR/Pajak/KM), dan Maintenance sekarang sinkron real-time otomatis lewat Firebase antar semua perangkat — Apps Script di bawah ini pun baca & tulis langsung ke Firebase yang sama, jadi tidak perlu Google Sheet, tidak perlu di-deploy sebagai Web App, dan tidak ada tombol/centang push-pull manual lagi di aplikasi ini.

Kalau sebelumnya sudah pernah pasang kode Apps Script ini: nomor WA tujuan yang tadinya SATU (WA_TARGET, dipakai bareng untuk semua notif) sekarang dipecah jadi DUA — WA_TARGET_ADMIN untuk notif KIR/Pajak/Service Berkala, dan WA_TARGET_OWNER untuk notif PO Baru — supaya Owner cukup dapat notif PO tanpa ikut kebanjiran pengingat perbaikan/kelengkapan kendaraan. Untuk mengaktifkan ini, buka lagi project di script.google.com → hapus semua kode lama → tempel ulang kode terbaru di bawah ini → isi ulang nomor Admin/Staff & Owner-nya masing-masing → Save (tidak perlu bikin trigger baru, trigger yang sudah ada tetap jalan otomatis pakai kode yang baru).

1. Ambil Database Secret Firebase: buka Firebase Console → buka project ekspedisi-jaya → klik ikon gerigi (Project settings) → tab Service accounts → scroll ke bawah sampai bagian Database secrets → klik "Show" lalu salin secret-nya.
2. Buka script.google.com → buat project baru (boleh kosong, tidak perlu terhubung ke Sheet apa pun) → hapus isi default → tempel kode di bawah ini.
3. Di kode, ganti FIREBASE_DB_SECRET dengan secret dari langkah 1.
4. Daftar gratis di fonnte.com, hubungkan nomor WA yang akan jadi pengirim, lalu salin Token-nya. Ganti FONNTE_TOKEN dengan token itu. Nomor tujuan sekarang dipisah dua supaya tidak tercampur: ganti WA_TARGET_ADMIN dengan nomor WA Admin/Staff (tujuan notif KIR/Pajak/Service Berkala — urusan kelengkapan & perbaikan kendaraan), dan WA_TARGET_OWNER dengan nomor WA Owner/Pimpinan (tujuan notif PO Baru saja) — masing-masing format 62xxx, boleh lebih dari satu nomor dipisah koma, dan boleh diisi nomor yang sama kalau memang belum perlu dipisah.
5. Klik ikon jam (Triggers) di sisi kiri editor → Add Trigger → pilih function checkAndNotify, jenis "Time-driven" → "Day timer" → pilih jam pengecekan (mis. 07.00–08.00) → Save. Tidak perlu Deploy sebagai Web App — trigger terjadwal saja sudah cukup. Notif dari function ini (KIR/Pajak/Service) terkirim ke nomor WA_TARGET_ADMIN.
6. Untuk notifikasi PO baru: tambah trigger kedua → Add Trigger → pilih function checkAndNotifyPoBaru, jenis "Time-driven" → "Minutes timer" → pilih "Every 5 minutes" (atau "Every minute" kalau mau paling cepat) → Save. Setiap ada PO baru yang diinput di menu "Input SO & Upload PO", WA notifikasi otomatis terkirim dalam beberapa menit ke nomor WA_TARGET_OWNER — tidak perlu buka aplikasi ini.
Opsional — tarik KM & lokasi/status GPS otomatis dari Cartrack: isi CARTRACK_USERNAME dan CARTRACK_PASSWORD di kode (dari akun Cartrack Fleetweb Anda, menu API Settings), lalu tambah trigger kedua untuk function syncOdometerFromCartrack, jenis "Time-driven" → "Minute timer" → pilih "Every 5 minutes" supaya Monitoring Armada selalu ter-update (jangan pilih interval jam-an seperti sebelumnya kalau mau lokasi selalu terkini — "Every 5 minutes" adalah interval tercepat yang wajar dipakai terus-menerus). KM, Lokasi Terakhir, dan Status (Berjalan/Berhenti) akan otomatis masuk ke Firebase dan langsung terlihat di halaman Maintenance Perbaikan & Monitoring Armada — tidak perlu tarik manual. Kalau trigger ini sudah pernah dibuat sebelumnya: tidak perlu dihapus/dibuat ulang, cukup klik ikon jam (Triggers) di kiri editor → klik trigger syncOdometerFromCartrack yang sudah ada → ubah interval waktunya jadi "Every 5 minutes" → Save.

Keamanan sistem (WAJIB dilakukan sekali di Firebase Console)

Login pakai Firebase Authentication sungguhan (Sesi ketigapuluhtujuh) + Security Rules diperketat untuk menutup celah promosi-diri-jadi-admin (Sesi ketigapuluhdelapan) + dukungan pembatasan akses data DO/PKB per-akun (Sesi ketigapuluhsembilan) — langkah di bawah ini perlu dilakukan SEKALI di Firebase Console supaya perlindungannya benar-benar aktif

Sebelumnya sistem "login diam-diam" ke Firebase (anonymous) + cek password di browser — cukup untuk gerbang tampilan, tapi bukan keamanan data sungguhan. Sekarang password dicek di server Firebase, dan akses baca/tulis database dikunci lewat Security Rules di bawah. Tanpa 2 langkah ini diterapkan, database masih memakai aturan lama (kemungkinan lebih longgar) — jadi jangan dilewati.

Kalau sudah pernah pasang Rules versi sebelumnya: tempel ulang kode di bawah ini & Publish lagi — satu kode ini sudah mencakup SEMUA perbaikan sampai sesi terbaru sekaligus, jadi cukup tempel yang ini saja, tidak perlu cari versi-versi lama. Ringkasan yang berubah sejak versi pertama: (1) field role, approved, bisaKonfirmasiPO di akun mana pun HANYA bisa diubah oleh akun yang sudah admin (menutup celah promosi-diri-jadi-admin) — konsekuensinya, fitur "daftar ulang pakai email lama langsung aktif otomatis" tidak berlaku lagi, SEMUA pendaftaran baru tetap perlu 1x klik "Setujui" dari admin; (2) node records (data DO/PKB) sekarang punya aturan sendiri yang mendukung fitur "Batasi akses data DO/PKB" per-akun di panel Akun terdaftar di bawah — akun yang dicentang tidak akan bisa membaca/menulis data DO sama sekali, ditegakkan di server (bukan cuma disembunyikan di tampilan); (3) field bisaEditRekapDO (izin edit/hapus/isi tonase/ubah status di halaman Rekap Data DO untuk akun non-admin) ikut dilindungi dengan pola yang sama seperti bisaKonfirmasiPO — kalau baru saja pasang Rules versi lama sebelum fitur ini ada, WAJIB tempel ulang kode di bawah supaya toggle "Bisa edit data Rekap Data DO" di panel Akun terdaftar tidak bisa dinaikkan sendiri oleh akun non-admin lewat luar aplikasi.

Buka Firebase Console → project ekspedisi-jaya → menu Authentication di sidebar kiri → tab Sign-in method → klik Add new provider (atau langsung klik barisnya kalau sudah ada di daftar) → pilih Email/Password → aktifkan (Enable) → Save. Kalau sebelumnya provider Anonymous juga aktif di daftar yang sama, boleh dimatikan sekarang (sudah tidak dipakai sistem ini lagi). Opsi "Email link (passwordless sign-in)" di bawahnya TIDAK perlu diaktifkan — sistem ini pakai password biasa.

Masih di Firebase Console → menu Realtime Database di sidebar kiri → tab Rules (atau Security Rules) → hapus semua isi kotak aturan yang ada → tempel kode di bawah ini → klik Publish. Efeknya: data (DO, kendaraan, PO, dll) cuma bisa dibaca/ditulis oleh akun yang sudah login DAN sudah disetujui admin (approved), field role/approved/bisaKonfirmasiPO/dataInputRestricted/bisaEditRekapDO di akun mana pun cuma bisa diubah oleh akun yang rolenya admin, dan akun yang ditandai dataInputRestricted tidak akan bisa membaca/menulis data DO/PKB sama sekali.

Catatan: aturan "accounts" (node lama) sengaja dikunci baca-saja (.write: false) — tidak dihapus, cuma dibekukan, supaya proses "daftar ulang pakai email yang sama" (lihat panel Akun terdaftar di bawah) masih bisa mencocokkan nama & akses dari akun lama untuk bahan pertimbangan admin. Node records punya aturan sendiri (terpisah dari $other) supaya bisa menambahkan syarat dataInputRestricted khusus untuk data ini — node lain (kendaraan, driver, PO, dll) TIDAK ikut terpengaruh fitur pembatasan ini, tetap memakai aturan $other seperti biasa.

Pemulihan darurat: kalau suatu saat node accountsV2 sampai kosong sama sekali tanpa satu pun akun admin (misalnya karena database ter-reset), Rules di atas TIDAK mengizinkan siapa pun mem-promosikan diri sendiri jadi admin lagi lewat aplikasi (itu memang sengaja, itulah yang diperbaiki di sini) — satu-satunya jalan adalah admin project Firebase menambahkan field role: "admin" dan approved: true secara manual lewat tab Data di Realtime Database (akses lewat Firebase Console selalu diizinkan, tidak terikat Rules ini).
